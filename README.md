# 工业设备故障诊断与边缘预警系统

这是一个使用模拟传感器数据搭建的设备预警 Demo。我想验证一件事：温度和振动不能用同一套规则清洗；而报警之后，运维人员也需要知道是哪个指标触发了判断，以及系统参考了哪些历史样本。
目前所有步骤都在一台电脑的 Python 程序中运行：先生成并清洗数据，再模拟边缘初筛和云端诊断，最后把结果导出给 ECharts 看板。项目没有连接真实设备，也没有把模型实际部署到边缘网关或云服务。


## 数据流设计

```
模拟采集(1s/点)
   │
   ├─ 慢变量（温度）→ 滑窗 IQR 截断 + 边界 Smooth
   └─ 快变量（振动）→ 中值滤波去噪，残差超 3σ 的尖峰保留（真实冲击不抹掉）
   │
   ├─ 边缘端：感知机（温度, 振动）二分类初筛 → 只把可疑窗口上传（省带宽）
   │
   ├─ 云端：温度 = f(振动) 多元回归 → 残差 |y-ŷ| > 3σ 自适应阈值 → 判异
   │        阈值每 30 点用"干净"近期残差重估（仅当窗口内告警 <3 个），跟随工况漂移
   │
   ├─ 云端：PCA(2) 降维 + KNN(k=3) 检索历史故障库 → 最近邻距离 + 诊断建议
   │
   └─ 导出 frontend/data.json → ECharts 看板点击联动溯源卡片
我是怎么处理这组数据的
main.py 每秒生成一条温度、振动记录，并向其中一段数据注入异常。先用前 100 个点建立温度与振动的回归基线，再对后续 100 个点做模拟推理。用于感知机和 KNN 的历史样本也是程序生成的，正常样本 100 条、故障样本 20 条。
清洗时先看信号是什么。 温度变化较慢，用滑动窗口 IQR 限制离群值；振动里的尖峰却可能是要找的信号，所以先用中值滤波处理背景波动，再保留与滤波结果差异超过 3σ 的点。缺失值通过时间序列插值处理，同一时间戳的重复记录保留第一条。温度序列另外标记连续越界点，用来区分单点异常和持续异常。
判断分两步演示。 代码用感知机对温度、振动做轻量初筛；回归模型根据振动估计温度，将实际温度与估计值的残差同阈值比较。阈值来自残差的 3 倍标准差：近期窗口积累到 30 个点，且窗口内的残差都没有超过当前阈值时，才重估阈值，避免把已报警的窗口用于更新。
出现疑似异常后，程序再用 KNN 检索训练集中的相近样本，并把匹配距离和预设的故障标签交给前端。ECharts 同时展示温度、振动、残差与阈值；点击图上的数据点，可以看到对应的告警信息和样本匹配建议。这些建议来自模拟训练集中的标签，不是维修人员核验过的诊断结论。
数据库设计做到了哪里
database/schema.sql 包含设备表、传感器热数据表、告警日志表、按月份命名的冷数据表示例、设备与告警联查视图，以及把旧记录从热表移到冷表的存储过程。(machine_id, record_time) 联合索引用于支持“按设备查一段时间”的查询。
这部分目前只提供 SQL 结构和过程示例。归档调度、冷热迁移的生产运行、查询性能提升，都还没有与 main.py 联通或做实测，不应把它当成已上线的数据库链路。
```

## 关键设计点

| 设计 | 解决什么问题 |
| --- | --- |
| 快慢变量差异化清洗 | 统一滤波会把振动的冲击特征抹平，导致早期点蚀漏报 |
| 连续性异常检测 | 单点越阈值多为噪声，连续 N 点越界才报，降低误报率 |
| 边缘感知机 + 云端重模型 | 带宽与算力分层：边缘秒级响应，云端只处理可疑样本 |
| PCA + KNN | 多维特征下欧氏距离失效（维度灾难），先降维再检索 |
| 自适应 3σ 阈值 | 概念漂移：环境温度/负载缓慢变化会让固定阈值失效 |
| 冷热分离 | 热表只留 7 天保证看板查询快，冷表按月分表供离线训练，过期直接 DROP |
| 联合索引 (machine_id, record_time) | 覆盖"按设备+时间范围"的高频查询，避免回表与 filesort |

注入的故障区间为第 150–160 点，系统命中的告警点正好是 150–159，无正常点误报。
当前边界与下一步
- “边缘端”和“云端”是同一进程里的处理分工；目前没有真实网关、网络上传或云端服务。因此“只上传可疑窗口”和“节省带宽”还是架构设想，不是已测出的收益。
- 代码中的回归模型只以振动预测温度，严格说是单自变量线性回归。KNN 的训练输入是温度、振动两维，PCA 配置也保留两维，因此这里不能把它写成已经完成有效降维或解决高维问题。
- 目前使用模拟正常／故障样本和预设标签。下一步可先接入真实设备记录或公开工业故障数据，补齐训练集与测试集隔离，再评估不同工况下的漏报和误报；之后再考虑真正分开部署边缘初筛与云端诊断。
